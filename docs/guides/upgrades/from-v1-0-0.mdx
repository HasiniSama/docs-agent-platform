:::caution Draft procedure
This procedure has not yet been run end to end against a populated installation. Rehearse it on a copy of your installation before you run it in production.
:::

This guide upgrades an existing WSO2 Agent Manager v1.0.0 Helm installation. The commands use the quick-start release names and namespaces. Substitute the names from your installation, and repeat the gateway steps for every gateway in every organization and environment.

## Breaking changes

| Change | Impact | Required action |
| --- | --- | --- |
| OpenChoreo moves from 1.2.0 to 1.2.8 | The CRDs are unchanged. A Helm upgrade of the Control Plane and Observability Plane reverts the service-account `client_id` entitlement patch. | Upgrade the four planes and re-apply the patch, as described in [Upgrade platform dependencies](./platform-dependencies.mdx). |
| ThunderID moves from 1.0.0 to 1.0.1 | Platform Thunder and each environment Thunder are separate releases. | Upgrade each instance separately. |
| Gateway Operator moves from chart 0.11.0 to 0.11.3 | Only the `llmprovidertemplates` CRD changes. Upgrading the operator does not redeploy existing gateways. | Apply the CRDs, upgrade the operator, and then trigger each gateway explicitly (Step 7). |
| API Platform gateway moves from images 1.2.1 to 2026.09.24 | The gateway controller's SQLite schema moves from version 4 to 5 with no in-place migration. The new controller refuses a version 4 database. | Delete each controller database immediately before its gateway redeploys. The controller resynchronizes from Agent Manager. |
| The Agent Manager database moves from migration 0043 to 0050 | Migrations 0044 to 0050 run in one transaction. v1.0.0 refuses to start against a database that contains them. | Back up PostgreSQL first. A chart rollback alone cannot restore v1.0.0. |
| The gateway catch-all route request timeout moves from 30 seconds to unlimited | Long-running and streaming requests are no longer cut off at 30 seconds. The gateway's 5-minute idle timeout still applies. | Review any client behavior that relied on the 30-second limit. |
| The platform Thunder bootstrap runs only at install time | The target adds a refresh-token lifetime and login-screen branding to the Console, CLI, and MCP clients. An upgrade does not apply these to existing clients. | Existing clients keep their v1.0.0 settings. |

## Prerequisites

- Helm 3.14 or later, for `--reset-then-reuse-values`. The target installer uses Helm 3.19.4.
- `kubectl` access to every cluster that runs an Agent Manager component.
- Access to the chart registry. For a subscription installation, use the registry and credentials assigned to your subscription.
- A maintenance window. Expect each gateway to be unavailable while it redeploys and its new controller resynchronizes.

## Step 1: Set variables and record the installation

```bash
export VERSION="0.0.0-dev"
export REG="oci://ghcr.io/wso2"
export AMP_NS="wso2-amp"
export DP_NS="openchoreo-data-plane"
export GATEWAY_CONTEXT="<gateway-cluster-context>"
export GW_VERSION="2026.09.24"
export GW_OPERATOR_VERSION="0.11.3"

helm version
helm list -A
kubectl --context "$GATEWAY_CONTEXT" get apigateways -A
```

Replace `<gateway-cluster-context>` with the Kubernetes context of the cluster that runs the Gateway Operator and your gateways. On a single-cluster installation, this is the output of `kubectl config current-context`. For development testing, set `VERSION` to the exact snapshot under test.

Record each Helm release, namespace, chart version, and Kubernetes context. Record every APIGateway with its namespace. The quick-start installer names them `api-platform-<org>-<env>` in the `<org>-<env>` namespace.

## Step 2: Back up

Pause deployments, promotions, and configuration changes for the maintenance window.

Save each release's history and user-supplied values. These files can contain credentials, so keep them out of source control:

```bash
umask 077
mkdir -p upgrade-backup
helm history amp -n "$AMP_NS" > upgrade-backup/amp-history.txt
helm get values amp -n "$AMP_NS" -o yaml > upgrade-backup/amp-user-values.yaml
```

Repeat for the other releases recorded in Step 1.

Back up the Agent Manager database. This dump is the only way back to v1.0.0. For the quick-start PostgreSQL instance:

```bash
kubectl exec -n "$AMP_NS" amp-postgresql-0 -- \
  pg_dump -U agentmanager -d agentmanager -Fc \
  > upgrade-backup/ams-1.0.0.dump
```

For an external database, use its own backup tooling. Test the restore in a separate database.

For each gateway, back up the controller data and its encryption key Secret. The key is mounted from the `gateway-encryption-keys` Secret, not stored on the volume. The data backup can restore the old 1.2.1 controller only. The new controller cannot read it.

```bash
export GW_NS="default-default"
GWC=$(kubectl --context "$GATEWAY_CONTEXT" get deploy -n "$GW_NS" -o name | grep gateway-controller)
kubectl --context "$GATEWAY_CONTEXT" exec -n "$GW_NS" "$GWC" -- tar cf - -C /app data \
  > "upgrade-backup/gw-data-$GW_NS.tar"
kubectl --context "$GATEWAY_CONTEXT" get secret gateway-encryption-keys -n "$GW_NS" -o yaml \
  > "upgrade-backup/gw-encryption-keys-$GW_NS.yaml"
```

Record a baseline: invoke representative agents, and note existing traces, monitor results, and API keys in use.

## Step 3: Upgrade OpenChoreo and Thunder

Follow [Upgrade platform dependencies](./platform-dependencies.mdx) through its environment Thunder step. Leave the Gateway Operator at 0.11.0 until Step 6.

## Step 4: Upgrade platform resources, then Agent Manager

Upgrade platform resources first. The target Agent Manager attaches a new `a2a-gateway-route` trait to A2A agents, and only the target platform resources chart defines it.

```bash
helm upgrade amp-platform-resources \
  "$REG/wso2-amp-platform-resources-extension" \
  --version "$VERSION" -n default \
  --reset-then-reuse-values --timeout 15m --wait

helm upgrade amp "$REG/wso2-agent-manager" \
  --version "$VERSION" -n "$AMP_NS" \
  --reset-then-reuse-values --timeout 15m --wait
```

The `amp-db-migration` post-upgrade hook applies migrations 0044 to 0050. Kubernetes deletes the job 300 seconds after it finishes, so read its logs right away:

```bash
kubectl logs -n "$AMP_NS" job/amp-db-migration
kubectl exec -n "$AMP_NS" amp-postgresql-0 -- \
  psql -U agentmanager -d agentmanager -tc \
  "select max(id) from migration_history"
```

The query returns `0050`. If the job fails, the transaction leaves the database at `0043`. Fix the cause, usually database connectivity or credentials, and rerun the same `helm upgrade amp` command.

## Step 5: Upgrade the observability and evaluation extensions

Skip any extension that is not installed.

```bash
helm upgrade amp-observability-traces "$REG/wso2-amp-observability-extension" \
  --version "$VERSION" -n openchoreo-observability-plane \
  --reset-then-reuse-values --timeout 15m --wait

helm upgrade amp-evaluation-extension "$REG/wso2-amp-evaluation-extension" \
  --version "$VERSION" -n openchoreo-workflow-plane \
  --reset-then-reuse-values --timeout 15m --wait
```

## Step 6: Upgrade the gateway extensions and the Gateway Operator

Upgrade each gateway extension release. This does not redeploy the gateway. Its pre-upgrade bootstrap job calls Agent Manager, which must be running the target version.

```bash
export GW_RELEASE="api-platform-default-default"
helm upgrade "$GW_RELEASE" \
  "$REG/wso2-amp-api-platform-gateway-extension" \
  --version "$VERSION" -n "$GW_NS" --kube-context "$GATEWAY_CONTEXT" \
  --reset-then-reuse-values --timeout 15m --wait
```

Apply the operator CRDs. Helm does not upgrade CRDs in a chart's `crds/` directory. The new CRDs keep serving the existing versions.

```bash
helm show crds \
  oci://ghcr.io/wso2/api-platform/helm-charts/gateway-operator \
  --version "$GW_OPERATOR_VERSION" \
  | kubectl --context "$GATEWAY_CONTEXT" apply --server-side --force-conflicts -f -
```

Upgrade the operator and pin the gateway chart and both gateway images. Setting only the chart version leaves the old images in place.

```bash
helm upgrade gateway-operator \
  oci://ghcr.io/wso2/api-platform/helm-charts/gateway-operator \
  --version "$GW_OPERATOR_VERSION" -n "$DP_NS" \
  --kube-context "$GATEWAY_CONTEXT" --reset-then-reuse-values \
  --set-string gateway.helm.chartVersion="$GW_VERSION" \
  --set-string gateway.values.gateway.controller.image.tag="$GW_VERSION" \
  --set-string gateway.values.gateway.gatewayRuntime.image.tag="$GW_VERSION" \
  --timeout 15m --wait
```

Chart 0.11.3 runs operator image 0.11.1. Existing gateways keep running 1.2.1 after this step.

## Step 7: Reset each controller database and redeploy its gateway

The operator redeploys an APIGateway only when its spec changes. For each gateway, delete the controller database and then change the spec, with no pause between the two commands. The running 1.2.1 controller keeps its open file until its pod stops. The extension sets the controller's rollout strategy to `Recreate`, so the new controller starts on an empty volume and creates a version 5 database.

:::danger
This deletes the controller's local state. Confirm the Step 2 backups and the Step 4 migration before you continue. Delete only these three files, and keep the encryption key Secret.
:::

```bash
export GW_NAME="api-platform-default-default"
GWC=$(kubectl --context "$GATEWAY_CONTEXT" get deploy -n "$GW_NS" -o name | grep gateway-controller)

kubectl --context "$GATEWAY_CONTEXT" exec -n "$GW_NS" "$GWC" -- rm -f \
  /app/data/gateway.db /app/data/gateway.db-wal /app/data/gateway.db-shm

kubectl --context "$GATEWAY_CONTEXT" patch apigateway "$GW_NAME" -n "$GW_NS" --type=merge -p \
  "{\"spec\":{\"infrastructure\":{\"annotations\":{\"upgrade.amp.wso2.com/gateway-version\":\"$GW_VERSION\"}}}}"
```

The operator passes `spec.infrastructure.annotations` to the gateway resources as common annotations. The patch only changes the spec, which triggers the redeploy.

Wait until the gateway reports the new generation as programmed:

```bash
kubectl --context "$GATEWAY_CONTEXT" get apigateway "$GW_NAME" -n "$GW_NS" -o jsonpath=\
'{.metadata.generation} {.status.conditions[?(@.type=="Programmed")].observedGeneration} {.status.conditions[?(@.type=="Programmed")].status}{"\n"}'
```

Repeat until the first two numbers match and the status is `True`. Then check the controller:

```bash
kubectl --context "$GATEWAY_CONTEXT" get pods -n "$GW_NS" -o jsonpath='{..image}' | tr ' ' '\n' | sort -u
kubectl --context "$GATEWAY_CONTEXT" logs -n "$GW_NS" "$GWC" | grep -E 'Initializing database schema|Control plane connection established|Deployment sync completed'
```

The images are `gateway-controller:2026.09.24` and `gateway-runtime:2026.09.24`, and all three log lines appear. Finish one gateway before you start the next.

## Step 8: Verify existing workloads

| Check | Command or action | Expected result |
| --- | --- | --- |
| Agent Manager images | `kubectl get pods -n "$AMP_NS" -o jsonpath='{..image}' \| tr ' ' '\n' \| sort -u` | The `amp-*` images use the target version. |
| Migration history | `select max(id) from migration_history` | `0050` |
| OpenChoreo planes | `helm list -A` | All four planes use chart 1.2.8. |
| OpenChoreo authorization | List projects in the Console. | Existing projects appear. An empty list with no errors means the `client_id` patch is missing. |
| Gateways | `kubectl get apigateways -A` | Each gateway is `Programmed=True` at its current generation. |
| Console gateway status | In the Console left sidebar, under **INFRASTRUCTURE**, click **Gateways**. | Each gateway is listed and active. |
| Invocation | Invoke an agent that uses an LLM Service Provider or MCP Proxy, with an existing API key. | The call succeeds through the gateway. |
| Deployment and promotion | Redeploy an existing agent and promote it. | Both succeed. |
| Observability and evaluation | Open a pre-upgrade trace and run a monitor. | Historical traces load, new traces arrive, and the monitor completes. |

Do not mark the upgrade complete because Helm reported success.

## Troubleshooting

| Symptom | Cause and action |
| --- | --- |
| The controller crash-loops with `unsupported schema version 4, expected 5; delete the database to recreate` | The old database survived, or the old controller recreated it before the rollout. The pod exits too quickly for `kubectl exec`. Override its command once to clear the database, then remove the override. See the commands after this table. |
| Gateway images stay at 1.2.1 | The operator did not redeploy the gateway. Check `helm get values gateway-operator -n "$DP_NS"` for both image tags, then repeat the Step 7 patch with a new annotation value. |
| Routes or API keys are missing after the reset | The controller syncs deployments from Agent Manager on its first connection only. Reconnects and the polling interval setting do not resync. Check the controller logs for the control plane connection, then restart the controller Deployment to retry. |
| APIGateway reports `Multi-Attach error for volume` | The old and new controller pods are on different nodes. Check that the controller Deployment uses the `Recreate` strategy, and delete the old controller pod. |
| Migration job fails | Read the job logs before the 300-second cleanup. Fix the cause and rerun `helm upgrade amp`. The database stays at `0043`. |
| Agent Manager images remain at v1.0.0 | An explicit image tag override in your values pins the old version. Remove it and rerun the upgrade. |
| OpenChoreo calls return empty lists or `403` | The plane upgrade reverted the `client_id` entitlement patch. Re-apply it as described in [Upgrade platform dependencies](./platform-dependencies.mdx). |

To clear a controller database when the pod crash-loops:

```bash
kubectl --context "$GATEWAY_CONTEXT" patch -n "$GW_NS" "$GWC" --type=json -p \
  '[{"op":"add","path":"/spec/template/spec/containers/0/command","value":["sh","-c","rm -f /app/data/gateway.db*; sleep 3600"]}]'
kubectl --context "$GATEWAY_CONTEXT" rollout status -n "$GW_NS" "$GWC"
kubectl --context "$GATEWAY_CONTEXT" patch -n "$GW_NS" "$GWC" --type=json -p \
  '[{"op":"remove","path":"/spec/template/spec/containers/0/command"}]'
```

## Recovery to v1.0.0

There is no chart-only downgrade after the database migration. Keep the installation in maintenance mode.

1. Stop the Agent Manager API by scaling its Deployment to zero.
2. Restore the database:

   ```bash
   kubectl exec -i -n "$AMP_NS" amp-postgresql-0 -- \
     pg_restore -U agentmanager -d agentmanager --clean --if-exists \
     < upgrade-backup/ams-1.0.0.dump
   ```

3. Roll back the Agent Manager and extension releases with `helm rollback`. The gateway extension's bootstrap job also runs on rollback and needs Agent Manager to be reachable. If it fails, rerun the rollback.
4. Restore the Gateway Operator pins to chart 0.11.0, gateway chart 1.2.2, and images 1.2.1. For each gateway, restore the controller data from its Step 2 backup and redeploy it.
5. Restore OpenChoreo and Thunder as described in [Upgrade platform dependencies](./platform-dependencies.mdx).

Restoring the database discards writes made after the backup. Repeat the Step 8 checks before you resume service.
