# Register an External A2A Agent

Register an [Agent2Agent (A2A)](https://a2a-protocol.org/) agent that runs outside WSO2 Agent Manager, so the platform stores its agent card for each environment. You can also route the agent through an environment's gateway, which puts gateway API keys, CORS, and authentication in front of it.

## How Agent Manager Fronts an External A2A Agent

Each environment of an externally-hosted A2A agent has its own card URL and its own routing. An environment is in one of two modes:

| Mode | What Agent Manager does | Where callers send requests |
|---|---|---|
| Direct (the default) | Fetches the card from the URL you register and shows it in the Console | The agent's own address |
| **Route through gateway** | Also publishes the agent to the environment's gateway, which forwards each call to the agent | The gateway URL the Console shows for the environment |

When you route an environment through the gateway, Agent Manager derives the gateway routes from the agent's card:

- The upstream address is the card URL with `/.well-known/agent-card.json` removed. A card at `https://agent.example.com/team/.well-known/agent-card.json` gives the upstream `https://agent.example.com/team`.
- Each JSON-RPC and HTTP+JSON interface in the card's `supportedInterfaces` keeps its path below that upstream. If the card lists JSON-RPC at `https://agent.example.com/team/a2a/jsonrpc`, callers send JSON-RPC requests to `<gateway-url>/a2a/jsonrpc`.
- The gateway serves the card at `<gateway-url>/.well-known/agent-card.json` and rewrites the URLs of the interfaces it fronts to point at itself.

## Prerequisites

- An agent that serves A2A protocol version `1.0` and is reachable at a public `http` or `https` address. Its card must include `name`, a non-empty `supportedInterfaces` list, and `skills`.
- A project to register the agent in.
- To route the agent through the gateway: an ingress gateway mapped to the environment. See [Environment Management](./environment-management.mdx).

## Step 1: Register the Agent

1. Open your project and click **Add Agent**, then select **External Agent**.
2. Enter a **Name** and, optionally, a **Description**.
3. Under **Agent Type**, select **A2A Agent**.
4. Click **Register**.

Registration does not ask for a URL. You register the card URL for each environment in the next step.

## Step 2: Register the Agent Card URL

1. Open the agent. In the left sidebar, under **Agent Lifecycle**, click **Configure**.
2. Click the **A2A** tab, then select the environment's tab.
3. In **Agent card URL**, enter the full URL of the agent's card, such as `https://agent.example.com/.well-known/agent-card.json`.
4. Click **Save**.

The **Agent Card** section on the agent's overview also links here through **Register agent card URL**.

The URL must point at a public host. Agent Manager rejects `localhost` and private, loopback, and link-local addresses.

Agent Manager then fetches the card. While it does, the card shows **Pending**. Once fetched, the panel shows the card's name, version, **Interfaces**, and **Skills**, with the fetch time. Click **View JSON** to see the whole card.

Agent Manager fetches the card with a 5-second timeout and rejects a card larger than 1 MiB. A failed fetch is retried with a growing delay of up to one minute. After 14 failed attempts the card shows **Failed** with the reason, and Agent Manager stops retrying. Fix the cause, then click **Refetch**.

To change the URL, click the edit icon next to it. To remove the URL and the stored card for the environment, click **Remove**.

## Step 3: Route the Agent Through the Gateway

Optional: skip this step if callers should keep reaching the agent directly.

The gateway can front the agent only when the card meets these conditions:

- The card URL ends in `/.well-known/agent-card.json` and has no query string.
- Each JSON-RPC or HTTP+JSON interface URL is on the same scheme, host, and port as the card URL, under the same base path.
- Each of those interfaces declares `protocolVersion` `1.0`, or no version.

The card must offer at least one JSON-RPC or HTTP+JSON interface that meets these conditions. The gateway skips interfaces that do not.

To turn on routing:

1. On the environment's **A2A** tab, turn on **Route through gateway**.
2. Optional: if the agent itself requires a credential, enter the header it expects in **Upstream header**, such as `X-API-Key`, and the credential in **Header value**. The gateway adds this header to every call it forwards to the agent.
3. Click **Save**.

You can also turn on **Route through gateway** while registering the card URL in Step 2.

Under **Gateway routing**, the status changes from **Publishing to gateway** to **Routed through gateway**, and the Console shows the agent's gateway URL with a copy button. If the status is **Gateway publish failed**, read the error, fix the cause, and click **Retry**.

### Upstream Credential Rules

The gateway stores the header value encrypted and never returns it. After you save, the Console shows "A value is stored." with **Replace** and **Clear** buttons instead of the value.

- The card URL must use `https` before you can store a value, so the gateway never sends the credential in cleartext.
- The header name may contain only letters, digits, `-`, and `_`, up to 255 characters. `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Upgrade`, `TE`, `Keep-Alive`, `Trailer`, and any `Proxy-*` header cannot be set.
- The value can be up to 8192 bytes, and cannot contain quotes, line breaks, `%`, control characters, or `{{`.
- While a value is stored, the card URL cannot move to another origin. Clear the stored value first, then change the URL.

## Step 4: Configure Gateway Security

Routing an environment through the gateway turns on API key security and CORS with the platform defaults. To change them:

1. Under **Gateway routing**, click **Security settings**.
2. In the **Gateway security** drawer, set **CORS Configuration**, **Agent Card CORS**, and **Endpoint Authentication** as for a platform-hosted A2A agent. See [Deploy an A2A Agent](./deploy-an-a2a-agent.mdx#step-2-configure-endpoint-settings).
3. Click **Apply**.

With **OAuth** selected, **Forward token to upstream** stays off. The gateway validates the caller's token and strips it before forwarding the call, so an externally-hosted agent never receives tokens issued by your identity provider.

## Step 5: Create an API Key

With API key security on, callers need an agent API key for the environment. Once the environment is routed through the gateway, open the agent and, under **Security** in the left sidebar, click **Credentials**. Create the key as described in [Secure Agent Endpoints with API Keys](./secure-agent-endpoints-with-api-keys.mdx#step-2-create-an-agent-api-key).

An externally-hosted agent has no deployment, so its keys work as soon as the environment is routed through the gateway.

## Step 6: Call the Agent Through the Gateway

Send a request to the gateway URL plus the interface path from the card. For a JSON-RPC interface at `/a2a/jsonrpc` under the card's base:

```bash
curl -X POST "<gateway-url>/a2a/jsonrpc" \
  -H "Content-Type: application/json" \
  -H "A2A-Version: 1.0" \
  -H "X-API-Key: <agent-api-key>" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "SendMessage",
    "params": {
      "message": {
        "messageId": "msg-1",
        "role": "ROLE_USER",
        "parts": [{"text": "Hello"}]
      }
    }
  }'
```

Replace `<gateway-url>` with the URL under **Gateway routing**, `/a2a/jsonrpc` with your agent's JSON-RPC path, and `<agent-api-key>` with the key from Step 5. An A2A client can instead fetch the card from `<gateway-url>/.well-known/agent-card.json` and use the interface URLs in it.

## Stop Routing Through the Gateway

1. On the environment's **A2A** tab, turn off **Route through gateway**.
2. Click **Save**, then click **Stop routing** to confirm.

Callers then need the agent's own address again, gateway API keys and CORS stop applying, and any stored upstream value is deleted.

Deleting the environment also withdraws the agent from its gateway and deletes the agent's API keys for that environment.
